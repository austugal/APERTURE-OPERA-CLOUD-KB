# Advance Deposit Handling, Parameters, and City Tax Configuration — Portugal Fiscal

Source: Internal OPERA configuration document covering Advanced Deposit Handling (Portugal-specific deposit refund functionality), Advanced Tax Handling for Deposits, and City Tax (Taxa Municipal de Turismo) configuration. Content originally in OPERA 5 screenshots, applies in equivalent form to OPERA Cloud with menu path translation.

## 1. Advanced Deposit Handling — Deposit Refund Functionality

### Why it matters in Portugal

Portuguese law requires hotels to issue a **credit note** at check-out or settlement when:
- The advance deposit posted before check-in exceeds the total consumed services during the stay
- An adjustment is made for any reason and the guest needs to be refunded for part of their stay

Without correctly configured deposit refund handling, the property creates fiscal documents that do not comply with the SAF-T and ATCUD numbering rules.

### Configuration

OPERA 5 path: Application Parameter CASHIERING > PORTUGAL DEPOSIT REFUND = Y.

OPERA Cloud equivalent: Administration > Enterprise > OPERA Controls > Cashiering > Deposit Refund Handling > Configured (Portugal mode).

### Behaviour after activation

When the deposit transaction is selected on the Billing screen, a right-click menu option **Deposit Refund** appears. Marking the deposit with an 'X' automatically selects the associated Deposit Ledger Tax Transaction.

Constraints:
- If a credit bill is already issued against the deposit and the bill number is already assigned, the transaction cannot be marked for refund. Once issued, it is closed.
- If more than one deposit transaction exists on the Billing window, only one deposit can be selected for refund at a time.

### Refund workflow

1. Click Deposit Refund.
2. Enter refund amount on the payment form.
3. System splits the deposit and its associated tax transaction based on entered value.
4. Entered amount must be **less than or equal to** the refundable amount.
5. If zero, positive, or greater than refundable, the system blocks with prompt: *"Amount entered cannot be greater than total deposit refund available."*
6. Once processed, a credit note is printed.

### Quick Check Out

At quick check out, the user is responsible for performing the deposit refund. Otherwise, a regular check out folio with a credit is printed in one folio (non-compliant in Portugal).

Procedure for reservations with overpayment at quick check out:
1. Mark the reservation with 'X'
2. Click the Billing button
3. Process the deposit refund
4. Then check out — two print outs are generated: Credit Note and check out folio

## 2. Advanced Tax Handling for Deposits

### Portugal fiscal requirement

Deposits must be posted with tax calculated on the deposit amount. Deposits are **not considered part of the debit folio**. If the deposit exceeds the revenue generated by the reservation, a credit bill is created.

### Configuration

Two settings required, in order:

1. **Advanced Deposit Handling** must be set to **Mode 4** in PT country mode.
   - OPERA Cloud path: Administration > Enterprise > OPERA Controls > Cashiering > Advanced Deposit Handling = 4
   - OPERA 5 equivalent: Application Setting CASHIERING > ADVANCED DEPOSIT HANDLING = 4

2. **Advanced Tax Handling for Deposits** application parameter becomes available only after step 1 is set. Set to **Y**.
   - OPERA Cloud path: same Cashiering controls group
   - OPERA 5 equivalent: Application Parameter CASHIERING > ADVANCED TAX HANDLING FOR DEPOSITS = Y

### Verification

After activation, deposit postings should show a separate tax line generated automatically with the correct VAT rate per Portuguese fiscal rules. Validate in the SAF-T export that deposit and tax appear as linked transactions.

## 3. City Tax Configuration — Taxa Municipal de Turismo

### Scope

City tax does not apply across all Portuguese territory. Only certain cities apply it (Lisbon, Porto, Faro, Cascais, Sintra, Madeira island municipalities, etc.). The consultant must confirm with the property:
- Whether city tax applies at the property location
- The amount per person per night
- Conditions: age exemptions, length-of-stay caps, low season vs high season variations, exempted guest types

The city tax operates as an **additional package**, adding a separate line on the rate breakdown.

### Step 1 — Create the Transaction Code

OPERA 5 path: Cashiering > Codes > Transaction Codes.

OPERA Cloud path: Administration > Financial > Transaction Management > Transaction Codes.

Configuration values:

| Field | Value |
|---|---|
| Code | 6500 (example) |
| Description | Taxa Municipal Turismo |
| Subgroup | TAX |
| Group | TAX |
| Transaction Type | Others |
| Adjustment Code | (leave blank unless specified) |
| Default Price | (blank, set per pricing schedule) |
| Generates Inclusive | Ticked |
| Manual Posting | (per property policy) |
| Inactive | Unticked |

### Step 2 — VAT 0% Generates Configuration (Updated Rule)

**Important update:** The city tax transaction code configuration was changed. VAT 0% must now be added as Generates Inclusive, mapped to **M99**.

Generates configuration for code 6500:

| Code | Description | Rule | Level |
|---|---|---|---|
| 7500 | IVA / VAT 0% | Percentage 0% | Transaction |

When editing the Generates line:
- Transaction Code: 7500
- IVA / VAT 0%
- **Tax exemption reason: M99 — Não sujeito; não tributado** (Portuguese SAF-T VAT exemption reason code M99: "Not subject; not taxed")
- Percentage: 0%

This ensures the city tax line is exempt from VAT but properly reported in the SAF-T file with the correct exemption reason code.

### Step 3 — Create the Package Code

OPERA 5 path: Rate Management > Packages > Codes.

OPERA Cloud path: Administration > Financial > Rate Management > Package Codes.

Configuration values:

| Field | Value |
|---|---|
| Code | TAXTUR |
| Short Description | Tax Tur |
| Description | Taxa Municipal Turismo |
| Property | (assign to property) |
| Arrangement Code | (blank unless required) |
| Forecast Group | (assign if forecasting) |
| Forecast Next | (per property policy) |

Transaction Details:
- Transaction Code: 6500 (the city tax trx code created in Step 1)
- **Tax Inclusive: Ticked (Yes)** — required with the new VAT 0% inclusive configuration

Attributes:
- **Add Rate Separate**: Selected (city tax appears as a separate line on the rate breakdown)
- Add Rate Combined: NOT selected
- Included in Rate: NOT selected
- **Sell Separate**: Ticked

Posting Rhythm: **Custom Posting Schedule (based on date range)** — required for variable city tax rates (e.g. only first 7 nights, seasonal variations, age-based exemptions).

Calculation Rule: **Per Adult**.

Item Inventory: (blank unless tied to inventory).

Save.

### Step 4 — Attach Package to Rate Codes

Once the TAXTUR package exists, attach it to all rate codes where the city tax must apply. Without this attachment, reservations created on those rates will not auto-generate the city tax line.

Path: Administration > Financial > Rate Management > Rate Codes > [select rate code] > Rate Code Packages > Add TAXTUR.

## 4. Portuguese SAF-T VAT Exemption Reasons — Reference Codes

For any VAT 0% or VAT-exempt transaction in Portugal, the correct exemption reason code is mandatory in SAF-T output. The most commonly used:

| Code | Description (Portuguese) | Use case |
|---|---|---|
| M99 | Não sujeito; não tributado | City tax, certain regulatory charges |
| M01 | Artigo 16.º, n.º 6 do CIVA | Specific VAT code article exemptions |
| M02 | Artigo 6.º do Decreto-Lei n.º 198/90 | Specific decree exemptions |
| M04 | Isento — Artigo 13.º do CIVA | Exemption under article 13 |
| M05 | Isento — Artigo 14.º do CIVA | Exemption under article 14 (exports, intra-EU) |
| M06 | Isento — Artigo 15.º do CIVA | Exemption under article 15 |
| M07 | Isento — Artigo 9.º do CIVA | Healthcare, education exemptions |
| M19 | Outras isenções | Other exemptions (catch-all, use with care) |
| M40 | IVA — autoliquidação | Reverse charge VAT |

The full list is maintained by the Portuguese tax authority (AT — Autoridade Tributária e Aduaneira) and must be mapped in OPERA's PORTUGAL_SAFT_VAT_EXEMPTION_REASONS LOV.

OPERA Cloud path: Administration > Enterprise > OPERA Controls > Cashiering > VAT Exemption Reasons (PORTUGAL_SAFT_VAT_EXEMPTION_REASONS).

## 5. Operational notes

### Lisbon City Tax (Taxa Municipal Turística de Lisboa)
- EUR 4 per person per night (as of 2024 update)
- Capped at 7 nights per stay
- Exemptions: under 13, on official duty with proof, medical treatment with proof
- Applies in all Lisbon Council parishes
- Calculation Rule: Per Adult, Posting Rhythm: First 7 nights

### Porto City Tax
- EUR 3 per person per night (as of 2024 update)
- Capped at 7 consecutive nights
- Same exemption rules as Lisbon
- Calculation Rule: Per Adult, Posting Rhythm: First 7 nights

### Cascais, Sintra, Madeira island municipalities
- Variable rates, often seasonal
- Verify per municipality before configuration
- Some municipalities exempt children under different age thresholds

## 6. Common errors during configuration

- City tax appearing on rate but no VAT 0% line in SAF-T: VAT 0% Generates Inclusive missing or M99 not mapped. Fix at Step 2.
- City tax posting for all nights instead of capped at 7: Posting Rhythm set to Per Stay or Per Night instead of Custom Posting Schedule. Fix at Step 3.
- City tax posting per room instead of per adult: Calculation Rule set to Per Room. Fix at Step 3.
- City tax included in rate (visible to guest but not as separate line): Add Rate Separate not selected, or Sell Separate not ticked. Fix at Step 3.
- Deposit refund credit note not printing at check-out: Application Parameter PORTUGAL DEPOSIT REFUND not set to Y, or Advanced Deposit Handling not set to Mode 4. Fix at Section 1 and 2.
- SAF-T export rejecting city tax line: VAT exemption reason M99 not mapped in PORTUGAL_SAFT_VAT_EXEMPTION_REASONS LOV. Fix at Section 4.

## 7. Tiago notes

- This document reflects OPERA 5 screenshots but the logic is identical in OPERA Cloud. Translate menu paths using the standard mapping: Cashiering > Codes > Transaction Codes (V5) = Administration > Financial > Transaction Management > Transaction Codes (Cloud).
- Mode 4 Advanced Deposit Handling is **Portugal-specific**. Do not apply it to non-PT properties — it changes the deposit-to-revenue ledger relationship in ways that break other country fiscal logic.
- The VAT 0% mapping with M99 is the most recent change to the configuration. Older properties built before this update need a retrofit. Validate in any property migration from OPERA 5 to Cloud that this mapping carried across correctly.
- For multi-property Portuguese portfolios (Lisbon, Porto), standardise the city tax package code, for example TAXTUR, across the portfolio for reporting consistency. Confirm the naming already in use with the property's support partner.
- ALMABAR likely already has TAXTUR configured. Verify the M99 mapping and the Custom Posting Schedule rhythm are correct. If the property opened pre-2022, the older configuration may still be active.
- For a Spanish property in the Balearic Islands: city tax is the Balearic Sustainable Tourism Tax (Impuesto de Turismo Sostenible), Spanish jurisdiction, different rules and exemption codes. Do not apply Portuguese M99 logic. Use the Spanish SII equivalent.
